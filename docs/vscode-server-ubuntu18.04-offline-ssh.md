# Deploying VS Code Server on Ubuntu 18.04 for Current VS Code via Remote-SSH (Offline, SSH-Only)

> **Goal:** Enable the current version of VS Code (>= 1.99, 2026) on your local machine (Windows / macOS / Ubuntu 20.04+) to develop on an **offline Ubuntu 18.04** host through the **Remote-SSH** extension, using **only** copy via `scp`/`sftp` and commands executed on the remote. No outbound internet on the remote, no `sudo`.

## 1. Background & Problem

### 1.1 Why Ubuntu 18.04 stopped working

- **Ubuntu 18.04 LTS (Bionic)** ships `glibc 2.27`, `kernel 4.15`, and an older `libstdc++`.
- **VS Code 1.86 (Jan 2024)** raised the server build toolchain to `glibc >= 2.28`, `libstdc++ >= 3.4.25`, `kernel >= 4.18` ([Remote Linux prereqs](https://code.visualstudio.com/docs/remote/linux)).
- **VS Code 1.99 (Mar 2025)** removed the legacy server pipeline entirely. The prebuilt `vscode-server` distributed at `update.code.visualstudio.com` is now **only** compatible with `glibc >= 2.28` distributions (Debian 10+, Ubuntu 20.04+, RHEL 8+). Attempting to run it on 18.04 produces:

  ```
  Missing GLIBC >= 2.28! from /lib/x86_64-linux-gnu/libc-2.27.so
  Error: Missing required dependencies. Please refer to our FAQ https://aka.ms/vscode-remote/faq/old-linux
  ```

### 1.2 Why "offline / SSH-only" matters

The 18.04 host has **no outbound HTTPS** — it cannot `curl https://update.code.visualstudio.com`. The `Remote-SSH` extension normally downloads `vscode-server` on the remote and falls back to a local download + transfer. Offline, both fail unless you **manually** stage the artifacts and copy them via `scp`/`sftp`.

This document solves **both** problems:

| Problem | Solution in this doc |
|---|---|
| Offline install (no internet on remote) | Manual download on local, copy to `~/.vscode-server/cli/servers/...` and `*.done` marker |
| `GLIBC_2.28 not found` on 18.04 | User-space glibc 2.31 sysroot + `mock-patchelf` wrapper + `spawn-patch.js` (no `sudo`) |

### 1.3 Terminology

- **Local / Client:** The machine where VS Code GUI runs.
- **Remote / Host:** The offline Ubuntu 18.04 machine.
- **Commit (`<COMMIT>`):** 40-character hex SHA of the VS Code build (e.g., `6c3e3dba23e...`). Determines the server binary path.
- **VS Code Server:** The Node.js-based server extracted to `~/.vscode-server/cli/servers/Stable-<COMMIT>/server/` on the remote.

## 2. Constraints & Non-Goals

**Assumptions:**

- Language: English.
- Privileges: **user-space only** — no `sudo`, no writes to `/lib`, `/usr`, `/etc`. Everything under `$HOME`.
- VS Code version: **current only** (>= 1.99, modern CLI layout). No legacy `~/.vscode-server/bin/<COMMIT>/`.
- Architecture: **x64 (`x86_64`) only**.
- Method: **pure manual step-by-step** — every action is copy-pasteable.

**Non-goals:**

- Upgrading the remote to 20.04/22.04.
- System-wide glibc replacement.
- Automated scripts.

## 3. Architecture Overview

```
Local VS Code (>=1.99, commit <COMMIT>)
   |
   |  Remote-SSH (SSH tunnel, port forward)
   v
Remote Ubuntu 18.04 (glibc 2.27, kernel 4.15)
   |
   +-- ~/.bashrc  (line 1: exports, BEFORE `case $-` early-return)
   |     exports VSCODE_SERVER_CUSTOM_GLIBC_LINKER
   |             VSCODE_SERVER_CUSTOM_GLIBC_PATH
   |             VSCODE_SERVER_PATCHELF_PATH
   |
   +-- ~/opt/glibc-2.31/                (unpacked from Focal libc6 deb, user-space)
   |     lib/x86_64-linux-gnu/ld-2.31.so
   |     lib/x86_64-linux-gnu/libc-2.31.so, libpthread, libm, ...
   |
   +-- ~/bin/
   |     mock-patchelf   (intercepts VS Code's patchelf call; creates wrapper)
   |     patchelf        (>=0.18, real binary)
   |     spawn-patch.js  (monkey-patches child_process.spawn)
   |
   +-- ~/.vscode-server/
         cli/servers/Stable-<COMMIT>/server/
            node          (wrapper script, NOT ELF, generated by mock-patchelf)
            node.real     (original Node ELF)
            out/..., bin/...
         vscode-cli-<COMMIT>.tar.gz.done  (marker, prevents re-download)
```

**How the workarounds interact:**

1. **Hard dependency:** `node` requires `GLIBC_2.28`. We supply glibc 2.31 and invoke `node` through `ld-2.31.so --library-path ...`.
2. **ELF patching segfault on kernel 4.15:** Instead of `patchelf --set-interpreter` rewriting ELF (segfaults on 4.15), `mock-patchelf` does `mv node node.real` and generates a wrapper that calls `ld-2.31.so` with `--library-path` and `NODE_OPTIONS=--require ~/bin/spawn-patch.js`.
3. **`process.execPath` fork bug:** When run via `ld.so`, `process.execPath` points to `ld.so`, so `fork()` tries to exec `ld.so` directly → `127`. `spawn-patch.js` patches `child_process.spawn` to reroute through the wrapper.
4. **Non-interactive `~/.bashrc` early-return:** `Remote-SSH` launches via `bash -c` (non-interactive). Default `~/.bashrc` has `case $- in *i*) ;; *) return;; esac`. Exports **must** be at line 1.

## 4. Prerequisites

- Local: VS Code installed. Get commit via `code --version` (second line) or `Help → About → Commit`. `scp`/`sftp` available.
- Remote: Stock Ubuntu 18.04 with `bash`, `tar`, `ar`, `mkdir` (all present by default).
- One-time: Determine `<COMMIT>` for your VS Code version and keep it for all steps.

## 5. Step 1 — Artifacts to Download Locally

*Run on local (has internet).*

| Artifact | Local filename | Source URL |
|---|---|---|
| VS Code Server | `vscode-server-linux-x64.tar.gz` | `https://update.code.visualstudio.com/commit:<COMMIT>/server-linux-x64/stable` |
| VS Code CLI (Alpine) | `vscode_cli_alpine_x64_cli.tar.gz` | `https://code.visualstudio.com/sha/download?build=stable&os=cli-alpine-x64` |
| Focal libc6 deb | `libc6_2.31-0ubuntu9.18_amd64.deb` | `http://security.ubuntu.com/ubuntu/pool/main/g/glibc/libc6_2.31-0ubuntu9.18_amd64.deb` |
| patchelf >=0.18 | `patchelf-0.19.1-x86_64.tar.gz` | `https://github.com/NixOS/patchelf/releases/download/0.18.0/patchelf-0.19.1-x86_64.tar.gz` |
| mock-patchelf | `mock-patchelf` | `https://raw.githubusercontent.com/sayoojd/vscode-old-glibc-fix/main/mock-patchelf` |
| spawn-patch.js | `spawn-patch.js` | `https://raw.githubusercontent.com/sayoojd/vscode-old-glibc-fix/main/spawn-patch.js` |

> **Version note:** The exact `libc6` patch version (`9.18`) drifts. Any `2.31-0ubuntu9.*` Focal deb works. If 404, browse `http://security.ubuntu.com/ubuntu/pool/main/g/glibc/` and pick latest `2.31` amd64 deb.

```bash
# run on local
mkdir -p /tmp/vscode-offline && cd /tmp/vscode-offline
COMMIT=YOUR_COMMIT_HERE   # e.g., 6c3e3dba23e... from `code --version`
curl -L "https://update.code.visualstudio.com/commit:${COMMIT}/server-linux-x64/stable" -o vscode-server-linux-x64.tar.gz
curl -L "https://code.visualstudio.com/sha/download?build=stable&os=cli-alpine-x64" -o vscode_cli_alpine_x64_cli.tar.gz
curl -L "http://security.ubuntu.com/ubuntu/pool/main/g/glibc/libc6_2.31-0ubuntu9.18_amd64.deb" -o libc6_2.31.deb
curl -L "https://github.com/NixOS/patchelf/releases/download/0.19.1/patchelf-0.19.1-x86_64.tar.gz" -o patchelf.tar.gz
curl -L "https://raw.githubusercontent.com/sayoojd/vscode-old-glibc-fix/main/mock-patchelf" -o mock-patchelf
curl -L "https://raw.githubusercontent.com/sayoojd/vscode-old-glibc-fix/main/spawn-patch.js" -o spawn-patch.js
```

## 6. Step 2 — Transfer Artifacts to Remote

*Run on local.*

```bash
# run on local
cd /tmp/vscode-offline
scp libc6_2.31.deb patchelf.tar.gz mock-patchelf spawn-patch.js vscode-server-linux-x64.tar.gz vscode_cli_alpine_x64_cli.tar.gz <user>@<host>:~/
```

Replace `<user>@<host>` with your SSH target (e.g., `vagrant` or `youruser@10.0.0.50`).

## 7. Step 3 — Unpack and Configure

*All commands in this section run on the remote server.*

### 7.1 Pre-clean stale artifacts (idempotent, before first connect)

```bash
# run on remote
rm -f ~/.vscode-server/vscode-cli-*.tar.gz* ~/.vscode-server/vscode-server.tar.gz* 2>&1 | head
```

### 7.2 Unpack glibc sysroot to `~/opt/glibc-2.31`

```bash
# run on remote
mkdir -p ~/opt/glibc-2.31 ~/bin /tmp/glibc-extract
cd /tmp/glibc-extract
ar x ~/libc6_2.31.deb
tar -xJf data.tar.xz -C ~/opt/glibc-2.31 --strip-components=1 2>&1 | head -n 20
```

### 7.3 Install patchelf and wrapper utilities to `~/bin`

```bash
# run on remote
tar -xzf ~/patchelf.tar.gz -C /tmp --strip-components=1 2>/dev/null
cp /tmp/bin/patchelf ~/bin/patchelf 2>/dev/null || cp /tmp/patchelf ~/bin/patchelf 2>/dev/null || find /tmp -name patchelf -exec cp {} ~/bin/patchelf \;
chmod +x ~/bin/patchelf ~/mock-patchelf ~/spawn-patch.js
mv ~/mock-patchelf ~/bin/mock-patchelf
mv ~/spawn-patch.js ~/bin/spawn-patch.js
chmod +x ~/bin/mock-patchelf
```

> `patchelf` 0.17.x segfaults with newer `node`. Ensure `>=0.18`.

### 7.4 Install environment hook (top of `~/.bashrc`)

Typical stock `~/.bashrc` has `case $- in *i*) ;; *) return;; esac` — everything after `return` is skipped for Remote-SSH's non-interactive `bash -c`. Exports **must** be at line 1.

Open `~/.bashrc` in an editor (`nano ~/.bashrc`, `vim ~/.bashrc`, or `code ~/.bashrc` if already connected) and **manually** prepend the following block at the very top of the file, before any other content:

```bash
# >>> vscode-glibc-fix >>>
export VSCODE_SERVER_CUSTOM_GLIBC_LINKER="$HOME/opt/glibc-2.31/lib/x86_64-linux-gnu/ld-2.31.so"
export VSCODE_SERVER_CUSTOM_GLIBC_PATH="$HOME/opt/glibc-2.31/lib/x86_64-linux-gnu:$HOME/opt/glibc-2.31/lib/x86_64-linux-gnu:/usr/lib/x86_64-linux-gnu"
export VSCODE_SERVER_PATCHELF_PATH="$HOME/bin/mock-patchelf"
# <<< vscode-glibc-fix <<<
```

After saving, the first 6 lines of `~/.bashrc` should be:

```bash
# >>> vscode-glibc-fix >>>
export VSCODE_SERVER_CUSTOM_GLIBC_LINKER="$HOME/opt/glibc-2.31/lib/x86_64-linux-gnu/ld-2.31.so"
export VSCODE_SERVER_CUSTOM_GLIBC_PATH="$HOME/opt/glibc-2.31/lib/x86_64-linux-gnu:$HOME/opt/glibc-2.31/lib/x86_64-linux-gnu:/usr/lib/x86_64-linux-gnu"
export VSCODE_SERVER_PATCHELF_PATH="$HOME/bin/mock-patchelf"
# <<< vscode-glibc-fix <<<
# ~/.bashrc: executed by bash(1) for non-login shells.
```

Do not place this block after the `case $-` early-return; otherwise it will be ignored in non-interactive `Remote-SSH` sessions.

### 7.5 Extract server and create CLI marker

```bash
# run on remote
COMMIT=YOUR_COMMIT_HERE   # same as Step 1
mkdir -p ~/.vscode-server/cli/servers/Stable-${COMMIT}/server
tar -xzf ~/vscode-server-linux-x64.tar.gz -C ~/.vscode-server/cli/servers/Stable-${COMMIT}/server --strip-components=1 --force-local
cp ~/vscode_cli_alpine_x64_cli.tar.gz ~/.vscode-server/vscode-cli-${COMMIT}.tar.gz.done
```

### 7.6 Wrap `node` with `mock-patchelf` (required)

```bash
# run on remote
COMMIT=YOUR_COMMIT_HERE
~/bin/mock-patchelf --set-interpreter ~/opt/glibc-2.31/lib/x86_64-linux-gnu/ld-2.31.so --set-rpath ~/opt/glibc-2.31/lib/x86_64-linux-gnu:/usr/lib/x86_64-linux-gnu ~/.vscode-server/cli/servers/Stable-${COMMIT}/server/node
```

### 7.7 Clean temporary files (optional)

```bash
# run on remote
rm -f ~/vscode-server-linux-x64.tar.gz ~/vscode_cli_alpine_x64_cli.tar.gz ~/libc6_2.31.deb ~/patchelf.tar.gz
rm -rf /tmp/glibc-extract 2>/dev/null
echo "cleaned"
```

## 8. Step 4 — Verify State

### 8.1 Connect from local VS Code

1. `Ctrl+Shift+P` → `Remote-SSH: Connect to Host...` → select your host.
2. Watch `View → Output → Remote-SSH`. Expected:

   ```
   Using commit id "6c3e3dba23..." and quality "stable" for server
   Using patchelf at /home/youruser/bin/mock-patchelf
   Setting interpreter to /home/youruser/opt/glibc-2.31/lib/x86_64-linux-gnu/ld-2.31.so
   Server started successfully
   ```

   Banner `Connected to an OS version that is not supported` is expected and non-blocking.

### 8.2 Verify on remote (single verification)

```bash
# run on remote
COMMIT=YOUR_COMMIT_HERE   # same as Step 1
echo "== glibc sysroot =="; ls -lh ~/opt/glibc-2.31/lib/x86_64-linux-gnu/ld-2.31.so; ~/opt/glibc-2.31/lib/x86_64-linux-gnu/libc.so.6 2>&1 | head -1
echo "== patchelf =="; ls -lh ~/bin/patchelf ~/bin/mock-patchelf ~/bin/spawn-patch.js; ~/bin/patchelf --version
echo "== bashrc hook =="; head -n 15 ~/.bashrc | head -n 10; bash -c "echo LINKER=\$VSCODE_SERVER_CUSTOM_GLIBC_LINKER; echo PATCHELF=\$VSCODE_SERVER_PATCHELF_PATH; ls -l \$VSCODE_SERVER_CUSTOM_GLIBC_LINKER \$VSCODE_SERVER_PATCHELF_PATH"
echo "== server ==="; ls -R ~/.vscode-server/cli 2>&1 | head -n 30; ls -lh ~/.vscode-server/cli/servers/Stable-${COMMIT}/server/node* 2>&1 | head; file ~/.vscode-server/cli/servers/Stable-${COMMIT}/server/node* 2>&1 | head -1
echo "== node ==="; ~/.vscode-server/cli/servers/Stable-${COMMIT}/server/node --version 2>&1 | head -1; cat ~/mock-patchelf-calls.log 2>&1 | tail -1
echo "== running ==="; ps aux | grep -E "vscode-server|node\.real|extensionHost" | grep -v grep | head -n 10
```

Expected:

- `GNU C Library (Ubuntu GLIBC 2.31-0ubuntu9.18) stable release version 2.31.` + `patchelf 0.19.1` + `LINKER=.../ld-2.31.so` + `PATCHELF=.../mock-patchelf`
- `node: Bourne-Again shell script`, `node.real: ELF 64-bit LSB executable` + `v24.18.1` (not `GLIBC_2.28 not found`)
- `ps aux` shows `node .../server/out/server-main.js` when VS Code is connected.

Also verify in VS Code terminal: `node --version; ldd --version | head -1; echo $VSCODE_SERVER_PATCHELF_PATH`
